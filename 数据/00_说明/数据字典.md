## 1. BTS 航班准点性能（On-Time Performance）

**文件**：`01_航班运行_BTS_OTP/原始压缩包/On_Time_Reporting_Carrier_On_Time_Performance_1987_present_YYYY_M.zip`
内含 1 个 CSV（110 列）+ `readme.html`（官方字段说明）。每月约 50–60 万行。

**观测单元（unit of observation）**：一次"报告承运人 × 航班号 × 航班日期"的**航段**，即一个 origin→dest 的计划飞行。
同一架飞机一天飞多段会产生多条记录；取消的航段**仍然在册**（这正是"消失的航班"能被计数的原因）。

### 1.1 标识与构型

| 字段 | 含义 | 备注 |
|---|---|---|
| `Year` `Quarter` `Month` `DayofMonth` `DayOfWeek` | 日期分解 | `DayOfWeek` 1=周一 |
| `FlightDate` | 航班日期（本地） | 格式 YYYY-MM-DD |
| `Reporting_Airline` | 报告承运人代码（IATA 两字码） | 与 `IATA_CODE_Reporting_Airline` 相同；`DOT_ID_Reporting_Airline` 为 BTS 内部 ID |
| `Tail_Number` | 飞机尾号 | 可用于同一架飞机的延误传播（late aircraft）分析；取消航班常为空 |
| `Flight_Number_Reporting_Airline` | 航班号 | 与日期、承运人构成唯一键 |
| `OriginAirportID` / `Origin` | 出发机场：BTS 机场 ID / IATA 三字码 | `OriginCityMarketID` 为城市市场（多机场城市合并） |
| `DestAirportID` / `Dest` | 目的机场 | 同上 |
| `OriginState` / `DestState` | 州 | |
| `Distance` | 航段距离（英里） | |
| `DistanceGroup` | 距离分组（每 250 英里一档） | |

### 1.2 时间与延误（本地时间，hhmm 整数）

| 字段 | 含义 |
|---|---|
| `CRSDepTime` / `CRSArrTime` | **计划**出发/到达时间 |
| `DepTime` / `ArrTime` | **实际**出发/到达时间（轮挡时间）；取消或未报告时为空 |
| `DepDelay` | 出发延误（分钟）= DepTime − CRSDepTime，负值=提前 |
| `DepDelayMinutes` | 同上但**负值截断为 0** |
| `DepDel15` | 出发延误 ≥15 分钟 = 1，否则 0 |
| `DepartureDelayGroups` | 出发延误分组：−2=提前>15min，−1=提前 1–15min，0=准点 0–14min，1=15–29min，…，12=≥180min |
| `ArrDelay` / `ArrDelayMinutes` / `ArrDel15` / `ArrivalDelayGroups` | 到达维度的同组定义 |
| `DepTimeBlk` / `ArrTimeBlk` | 计划时刻所在小时段（如 `0800-0859`），用于"一天中的时段"比较，**避免按实际时间分箱带来的内生性** |
| `TaxiOut` / `TaxiIn` | 滑出/滑入时间（分钟） |
| `WheelsOff` / `WheelsOn` | 离地/接地时间 — 把"地面滑行"与"空中"延误分离的关键 |
| `CRSElapsedTime` / `ActualElapsedTime` / `AirTime` | 计划轮挡时间 / 实际轮挡时间 / 空中时间 |

> ⚠️ **跨零点陷阱**：`ArrTime` 是 hhmm，跨午夜航班不能直接相减；`ArrDelay` 由 BTS 已算好，**必须直接使用**。

### 1.3 结果状态（本题的核心）

| 字段 | 含义 | 取值 |
|---|---|---|
| `Cancelled` | 是否取消 | 1.00 / 0.00 |
| `CancellationCode` | 取消原因 | A=承运人，B=天气，C=国家空域系统(NAS)，D=安全；**非取消航班为空** |
| `Diverted` | 是否改道 | 1.00 / 0.00 |
| `Flights` | 航班计数 | 恒为 1，用于加总 |

> **口径要点**：取消航班的 `DepTime`/`ArrTime`/`ArrDelay` 全为空；改道航班是否真正到达原目的地要看 `DivReachedDest`。
> 因此 `ArrDelay` 的缺失**不是随机缺失**（MNAR）：它恰恰对应最不可靠的那部分航班。

### 1.4 延误原因分解（仅部分航班填写）

| 字段 | 含义 |
|---|---|
| `CarrierDelay` | 承运人自身原因（机组、维修、加油、登机等） |
| `WeatherDelay` | 极端天气（仅指"实际发生且无法合理预防"的天气，不含因预期天气而做的调度） |
| `NASDelay` | 国家空域系统：非极端天气、机场运行、交通量、跑道关闭等 |
| `SecurityDelay` | 安检、登机口违规等 |
| `LateAircraftDelay` | 上一段晚到导致的连带延误 |

> **重要**：这 5 项**只对 `ArrDel15 = 1` 且未取消、未改道的航班填写**（合计应等于 `ArrDelayMinutes`）。
> 它们来自**承运人自报**，是"归因"而非"独立核实的根因"，且只覆盖全部航班中的一小部分。

### 1.5 改道明细

| 字段 | 含义 |
|---|---|
| `DivAirportLandings` | 改道后降落次数（0–5） |
| `DivReachedDest` | 改道后**是否最终抵达原目的地**（1/0） |
| `DivActualElapsedTime` / `DivArrDelay` / `DivDistance` | 改道航班的实际耗时/到达延误/额外距离 |
| `Div1Airport` … `Div5Airport` | 依次降落的备降机场（IATA） |
| `Div1WheelsOn` / `Div1TotalGTime` / `Div1LongestGTime` / `Div1WheelsOff` | 各次备降的接地时间、地面停留总时长/最长时长、再次离地时间 |
| `FirstDepTime` / `TotalAddGTime` / `LongestAddGTime` | 首次起飞时间 / 总附加地面时间 / 最长附加地面时间 |

## 2. 逐小时气象（IEM，含 2026 年）：`02_天气_气象/METAR_IEM/ASOS_<机场>_<年>.csv`

来源：Iowa Environmental Mesonet（IEM）ASOS 归档，原始数据即 NOAA/NWS METAR。
每机场每年约 **8,700 行**（逐小时；2026 年截至 9-30 约 6,500 行）。**覆盖全部 20 座机场 × 4 年**。

| 列 | 含义 | 单位 |
|---|---|---|
| `station` | 站点代码（ANC/HNL 在 IEM 中记为 PANC/PHNL） | |
| `valid` | 观测时间（**UTC**） | |
| `tmpf` / `dwpf` | 干球温度 / 露点 | °F |
| `relh` | 相对湿度 | % |
| `drct` / `sknt` | 风向 / 风速 | 度 / 节 |
| `gust` | 阵风 | 节 |
| `vsby` | 能见度 | 英里 |
| `skyc1` `skyc2` `skyc3` | 云层覆盖：`CLR`(晴) `FEW`(少) `SCT`(疏) `BKN`(多云) `OVC`(阴) `VV`(垂直能见度) | |
| `skyl1` `skyl2` `skyl3` | 对应云底高 | 英尺 |
| `p01i` | 1 小时降水量 | 英寸 |
| `wxcodes` | **当时天气代码**，空格分隔：`RA`雨 `SN`雪 `TSRA`雷雨 `FZRA`冻雨 `FZSN`冻雪 `BR`轻雾 `FG`雾 `HZ`霾 `GR`冰雹 `SQ`飑 … | |
| `ice_accretion_1hr` | 1 小时积冰 | 英寸 |
| `peak_wind_gust` | 时段内峰值阵风 | 节 |
| `feel` | 体感温度 | °F |

缺失标记：`M`（缺测）；`T`（痕量，降水 `<0.005 in`）。

## 3. 逐小时气象（NCEI 原始归档）：`02_天气_气象/LCD_逐小时/<机场>_<站号>_<年>.csv`

来源：NOAA NCEI **Local Climatological Data (LCD)**，与 METAR 同源但直接来自原始归档，**125 列**。
命名：`<IATA>_<USAF><WBAN>_<年>.csv`。时间列 `DATE` 为**当地标准/夏令时间**（无时区后缀）。

覆盖：19 座机场 × 2023–2025（DEN 未发布 LCD；2026 年目录尚未公开）。

关键列（其余为日/月汇总与短历时降水统计）：

| 列 | 含义 | 单位 |
|---|---|---|
| `REPORT_TYPE` | 报文体裁：`FM-15`=例行每小时 METAR，`FM-12`=SPECI 特选，`FM-16`=例行合成，`SOD`=日汇总 | |
| `SOURCE` | 观测来源代码 | |
| `HourlyDryBulbTemperature` / `HourlyDewPointTemperature` | 干球/露点温度 | °C（注意与 IEM 的 °F 不同） |
| `HourlyRelativeHumidity` | 相对湿度 | % |
| `HourlyWindDirection` / `HourlyWindSpeed` / `HourlyWindGustSpeed` | 风向/风速/阵风 | 度 / m·s⁻¹ |
| `HourlyVisibility` | 能见度 | 英里 |
| `HourlySkyConditions` | 云况文本，如 `BKN:07 200 OVC:08 250`（云量:云底高(百英尺)） | |
| `HourlyPresentWeatherType` | 天气现象代码串，如 `RA:01`、`TS:01`、`SN:02` | |
| `HourlyPrecipitation` | 小时降水量 | 英寸 |
| `HourlyAltimeterSetting` / `HourlySeaLevelPressure` / `HourlyStationPressure` | 气压 | 英寸汞柱 / 百帕 |
| `HourlyPressureTendency` / `HourlyPressureChange` | 气压倾向/变压 | |
| `DailyPrecipitation` / `DailySnowfall` / `DailySnowDepth` | 日降水量/降雪/雪深 | 英寸 |
| `DailyMaximumDryBulbTemperature` / `DailyMinimumDryBulbTemperature` | 日最高/最低气温 | °C |
| `ShortDurationPrecipitationValue0xx` | 短历时（5–180 分钟）降水强度统计 | 英寸 |

> 三个来源**互相独立可校验**：IEM 与 LCD 都是 ASOS 观测（°F vs °C、整点 vs 含 SPECI），
> GHCN 为质量控制后的日值。建模建议以 **LCD 为主源（2023–2025）**、
> **IEM 为 2026 年与交叉校验源**、**GHCN 为气候基准**。

## 4. 逐日气象：`02_天气_气象/GHCN_Daily/USW000<WBAN>.dly`

来源：NOAA NCEI GHCN-Daily。**定宽文本**，每行 = 站点(11) 年(4) 月(2) 要素(4) + 31 组(值5 缺测标志1 质量标志1 来源标志1)。
要素：`PRCP` 降水(0.1mm) `SNOW` 降雪(mm) `SNWD` 雪深(mm) `TMAX`/`TMIN` 最高/最低气温(0.1°C) `TAVG` `AWND` 平均风速(0.1m/s) `WSFG` 阵风。
值 `-9999` 表示缺测。质量标志 `S` 表示来自 ASOS 的"疑似"值，`G` 为估算值。
站点清单见 `ghcnd-stations.txt`，格式说明见 `readme.txt`。**含 1940 年代至今的完整历史**，可用于构造气候基准。

## 5. 飓风：`02_天气_气象/飓风HURDAT2/*.txt`

HURDAT2 最佳路径，两段式：
① 风暴头行：`AL092023, LEE, 78,`（ID、名称、记录数）
② 每个记录：日期、时间(UTC)、记录标识、**状态**(TD/TS/HU/EX/SD/SS/LO/WV/DB)、纬度、经度、最大持续风(kt)、最小中心气压(mb)、34/50/64 节风圈四象限半径。
字段定义见 `hurdat2-format-atlantic.pdf`。覆盖：大西洋 1851–2025、东北太平洋 1949–2025。

## 9. 时间口径（极易出错）

1. **BTS 的 `CRSDepTime`/`DepTime`/`ArrTime` 是机场本地时间**，跨时区航班两端不在同一时区；做时长计算请用 `CRSElapsedTime`/`ActualElapsedTime`（BTS 已按时区换算）。
2. **IEM 的 `valid` 是 UTC**；**LCD 的 `DATE` 是当地时间**；两者不可直接拼接。
3. **夏令时**：3 月第二个周日 – 11 月第一个周日为 EDT/CDT/MDT/PDT。`DepTime` 缺失的 02:00–02:59 在春季切换日不存在。
4. TSA 为美国东部日期口径；HURDAT2 为 UTC。

## 10. 建议的派生指标（供建模直接使用）

设某机场 $a$、时段 $t$，航班集合 $F_{a,t}$（到达该机场的**计划**航班）：

| 指标 | 定义 | 说明 |
|---|---|---|
| 计划航班量 | $\lvert F \rvert$ | 分母必须是计划航班，不能只用已执行航班 |
| 准点率（A14 口径） | $\#\{ArrDelay<15\}/\lvert F\rvert$ | 分子不含取消与改道 |
| 取消率 | $\#\{Cancelled=1\}/\lvert F\rvert$ | |
| 改道率 | $\#\{Diverted=1\}/\lvert F\rvert$ | |
| **行程中断率** | $\#\{Cancelled \lor ArrDelay\ge 15 \lor (Diverted \land \neg DivReachedDest)\}/\lvert F\rvert$ | **旅客视角主指标** |
| 准时到达率 | $\#\{ArrDelay \le 0\}/\lvert F\rvert$ | 与"准点率"不同的严格口径 |
| 严重延误率 | $\#\{ArrDelay \ge 60\}/\lvert F\rvert$、$\ge 180$ | |
| 到达延误分布 | $ArrDelay$ 的 P50/P90/P99（仅已完成航班） | 必须与中断率同时报告 |
| 期望行程时间惩罚 | $\mathbb{E}[\max(0, ArrDelay)] + P_{cancel}\cdot\mathbb{E}[\text{重新预订代价}]$ | 需假设重订代价，属推断量 |

> 现成的日度聚合已算好：`整理数据/机场日度_到达_全美.csv.gz` 与 `机场日度_出发_全美.csv.gz`
> 直接给出 `arr_flights / arr_cancelled / arr_diverted / arr_delay_sum / arr_delay30/60/180` 等列。
